当前规格：`../../PRD.md` V0.30 §0.6；技术实现：`../../TECH.md` V0.30；历史决策：`../../DISSCUSION.md`，本轮见一百三十二—一百五十八节。弱化职位六阶段及三栏对齐、直属展示、操作与状态视觉层级、标题统计、同职位等高同步滚动、组织待处理汇总、两栏同步职位标题与零总编展示及人编表单标题／归属行布局、标准部门树选择已实现并验证（2026-11-17），详见 `验收记录-弱化职位.md`。本文只说明运行、入口、验证和接入边界，字段规则以 PRD 为准。

## 运行与预览

Vue 3 + Ant Design Vue 4 + dayjs，使用本地 vendor；浏览器无需构建或后端。Node 仅用于测试。

```bash
python3 <skill-root>/scripts/serve.py --dir "原型/组织调整" --page "index.html" --port <本工作树端口>
```

通过输出的 HTTP 地址预览，不使用 file://。不同工作树使用不同端口，避免 localStorage 相互影响。Git 提交、main 合并及 GitHub Pages 发布流程见 TECH §7.1；发布内容从已提交 main 的本目录平铺到 gh-pages 根目录，排除本 README。

## 页面与业务入口

| 页面 | 作用 |
| --- | --- |
| index.html | 方案列表、筛选、新建方案弹框、演示数据重置 |
| 02-新建方案.html | 新建方案直达兼容页；正常入口为列表弹框 |
| 03-工作台.html | 组织／编制／人员三栏；组织范围驱动、独立人编分组与搜索、多选、组织拖拽、职位管理、范围补充、Undo／Redo；前后对比和提交弹框 |
| 04-前后对比.html | 工作台嵌入的对比／提交确认页，保留直达兼容入口 |
| 05-方案详情.html | 审批、版本与附件占位、生效结果、演示状态流转 |
| 06-演示自测.html | 内部数据层自测和故障注入；非业务页面 |

工作台顶部“编辑方案信息”可修改方案名称、调整层级、调整原因和详细原因；生效日期只读；调整范围在同一弹框中维护，显式根无有效影响时可移除。名称／编制编码点击展示详情占位提示；组织从操作菜单编辑，职位从“管理职位”维护，管理入口也提供于人编表单。组织可拖拽排序，职位在管理弹框“调整顺序”。完整字段见 PRD F-02—F-06。

编制无可展示明细时，内容区居中显示一次“暂无可用空编”，搜索无结果显示“未找到匹配的编制”；有招聘预留或已减编记录时不显示空态。编制标题及职位标题后显示总编／空编，空编为 0 且有编制时显示满编；人员和可用空编只可拖到组织，再手选职位。人员与编制多选互斥，勾选／全选及拖拽另一类对象时清空原选择；点击任一人编列表纯空白退出选择，数据行、标题及操作控件不触发取消。批量表单统一可编辑属性；三栏顶部对齐，当前仅展示选中组织直属数据，无额外范围栏或“含下级组织”开关；自动匹配也只处理当前组织直属职位。可点击操作提供手型提示。基准编制减编保留原位恢复行，新增净零直接消失；恢复不恢复人编绑定。对比使用单一“人员和编制”开关，图内恢复紫条职位节点，人员与编制沿细线归属展开；空职位过滤及完整职位差异审阅沿用现状（CMP-42）。

## 演示数据与兼容

- 案例一 `plan-case1`：范围内 9 职位、24 在职员工、28 编制、4 可用空编。
- 案例二 `plan-case2`：范围内 8 职位、18 在职员工、3 未来人员、26 编制、4 可用空编；有需求预留和停用阻断案例。
- `scopeDemo`：独立的范围／时间轴／在途编制流程校验数据，不进入预置方案列表。
- 华东数据：只供第 13 章数据自测使用。
- 当前 schema v11；兼容 v7—v10，保留方案和既有修改，补充缺失字段。未知新业务字段使用“默认”占位；损坏或不支持的数据结构才重建。不要把“演示重置”当作升级步骤。
- 字典关联使用稳定 ID；默认人员不占职位或编制。新增对象显示占位编码；职级按 P/M 序列格式。UI 定位与列表列宽按既有键保存。
