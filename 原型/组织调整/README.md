Vue 3 + Ant Design Vue 4 + dayjs，使用本地 vendor；浏览器无需构建或后端。Node 仅用于测试。


## 页面与业务入口

| 页面 | 作用 |
| --- | --- |
| index.html | 方案列表、筛选、新建方案弹框、演示数据重置 |
| 02-新建方案.html | 新建方案直达兼容页；正常入口为列表弹框 |
| 03-工作台.html | 组织／编制／人员三栏；组织范围驱动、独立人编分组与搜索、多选、组织拖拽、职位管理、范围补充、Undo／Redo；前后对比和提交弹框 |
| 04-前后对比.html | 工作台嵌入的对比／提交确认页，保留直达兼容入口 |
| 05-方案详情.html | 审批、版本与附件占位、生效结果、演示状态流转 |
| 06-演示自测.html | 内部数据层自测和故障注入；非业务页面 |

工作台顶部“编辑方案信息”可修改方案名称、调整层级、调整原因和详细原因；生效日期只读；调整范围在同一弹框中维护，显式根无有效影响时可移除。名称点击展示详情占位提示；编制编码可查看本轮占用、预留与期限详情；组织从操作菜单编辑，职位从“管理职位”维护，管理入口也提供于人编表单。组织可拖拽排序，职位在管理弹框“调整顺序”。完整字段见 PRD F-02—F-06。

编制面板按 PRD §0.8 精简：标题后显示非零统计，职位仅显示总编／可用空编。行内按编码、两胶囊标签位、信息和操作对齐；胶囊同行。窗口小于 1280 CSS px 时，信息与操作放到第二行，操作右对齐；职位标题及统计可换行，全选／增编另行靠右。浮动人数气泡显示姓名和期限；可用编制行尾统一“操作⌄”，菜单依次为绑定员工、绑定兼职、分隔线、调编、复制、减编；复制仍支持数量。占用行支持解除绑定／停止兼职／整批取消浮动；取消浮动后成为普通空编，人员转待绑编。招聘需求／Offer、姓名为详情占位。

人员标题为主职／长期兼职／短期兼职，主职始终显示，长期／短期为 0 时隐藏对应项及分隔符，在所选部门直属范围按主职优先、长期其次、短期最后去重。兼职行调岗调整主职；未来安排直接放在职位明细中，当前人员未来调出／离职通过当前行未来胶囊查看。未来审批中调入不锁编；未来事项不参与当前人员多选。状态原因点击查看，短期截止日期留在表单和详情。

两栏选择互斥，编制全选仅选择可用空编。自动匹配在当前组织各直属职位内处理应占编未绑定任职，排除不占编和异常空编；待绑定与异常阻止提交。共享职位等高与滚动、基准减编原位恢复、新增净零和撤销／重做沿用；恢复不恢复人员绑定。浮动逐人解除仍保留其余占用，取消浮动则整批释放。



### 调岗自动占编（2026-11-18）

人员可拖到组织、两栏职位标题或可用空编，沿用调岗表单确认；组织落点先选职位，所有入口只自动分配最终职位的合法空编。普通带编保留原绑定，不匹配仍移动并提示异常；浮动人员只释放本人原绑定，不携带原浮动名额。未分配到的应占编人员先移动、标待绑编，提交前必须解决。具体空编落点不带原编；同职位浮动／未绑定应占编人员仅绑定。表单可查看逐人分配，支持整批撤销。

组件映射：沿用 Modal、DeptTreeSelect、职位 Select、EmployeeSelect；编制安排使用现有提示样式和折叠明细。需求评估通过，主流程及分配顺序已确认；正式应占编来源等既有接入边界不变。

- 当前 schema v11；兼容 v7—v10，保留方案和既有修改，补充缺失字段。未知新业务字段使用“默认”占位；损坏或不支持的数据结构才重建。不要把“演示重置”当作升级步骤。
- 字典关联使用稳定 ID；角色字典中的“默认”占位人员不占职位或编制。新增对象显示占位编码；职级按 P/M 序列格式。UI 定位与列表列宽按既有键保存。

## 案例二复杂场景验证路径

进入“技术部组织拆分方案（含未来人员与停用冲突）”，点击产品部卡片空白处，查看产品经理：

- 总编 13＝主职 5＋长期兼职 1＋短期兼职 1＋浮动 1＋预留 4＋可用空编 1。
- 当前主职 9 人，含浮动共占 2 人、不占编 1 人、待绑定 1 人及编制职级异常 1 人；另有长期／短期兼职各 1。
- 通过 5 条紧凑未来行及 4 名当前人员的未来胶囊查看共 9 个事件：同一招聘需求下的 Offer／待入职、无 Offer 入职、批准／审批中调入，以及批准／审批中调出和离职。审批中调入王十显示“尚未锁定编制”；当前调出／离职人员保留占用。
- 初始待绑定孙七与异常陈明会阻止提交。可先自动匹配孙七；解除陈明绑定，变更可用编制 202611080129 的职级为 P4-2，再自动匹配；其他正常未来事件不会阻断提交。可用 Undo 逐步恢复。
- 现有暂存方案不会自动加入种子。可新建案例二方案加载；列表“演示数据重置”会清除本地址全部演示方案及修改，操作前留意确认提示。本轮验证没有清除用户已有方案。
